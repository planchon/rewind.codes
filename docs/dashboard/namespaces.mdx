Each end user of your product has a [namespace](/concepts/end-users). The Namespaces view shows them all for a month,
with their use against their limits. It needs `namespaces:read`.

  <img src="/images/dashboard/namespaces-dark.webp" alt="The Namespaces view: the ceiling, the default limits, and each end user's use as meters" className="hidden dark:block" />
</Frame>

- **The alerts of the month** come first: each limit an end user, or your organization, crossed, and when.
- **The first row** of the table is your organization: its ceiling, with the totals of every end user. The defaults and the end
  users fold under it.
- **Defaults** are the limits of every end user without exceptions. **Edit the defaults** changes them in a dialog,
  with `namespaces:write`.
- **Then each end user**, sorted by CPU, runs or scripts of the month, or by name. Each quota is a meter: orange from
  80 %, red at 100 %. A CPU time above its quota shows its share (`160%`): CPU is never refused, only alerted on.
- **Search** by the start of a name or of a display name (any case) in the query bar, which suggests the names as
  you type, and **At 80 % or more** keeps those near a limit.

An end user you gave a **display name** shows it in every view: this one, Observability, a run's details, Scripts,
the filters and the suggestions of the query bar. Hover it to see the namespace's id, which stays what links, the
query (`namespace:`), tokens and webhooks use.

## One end user

Open an end user, from this list or the picker at the top of the page, to look at them alone: every view then answers
for them ([Every end user, or one](/dashboard/introduction#every-end-user-or-one)). How their runs went is their
Overview, their runs are their Observability, their secrets their [Secrets](/dashboard/secrets). Their **Usage**, the
last entry of the sidebar, shows their month against their limits.

| Part | Shows |
| --- | --- |
| **Alerts** | Shown first, when there are any: every limit crossed this month, and whether the `quota.alert` webhook was sent. Their Overview shows them first too |
| **Cumulative CPU** | CPU time over the month against the quota, with the days it reached 80 % and 100 % |
| **Limits and use** | Each limit, the end user's use of it, and whether it is an exception to the defaults |
| **Tokens and exceptions** | The tokens in use, and the exceptions to the defaults |

The arrows next to the month go back in time.

## Actions

| Action | Needs | Does |
| --- | --- | --- |
| **Rename** | `namespaces:write` | Sets its display name in a dialog; emptied, removes it. Its id never changes |
| **Edit its limits** | `namespaces:write` | Sets its exceptions in a dialog: more for a paying user, `0` active runs to block someone |
| **Revoke its tokens** | `tokens:write` | Revokes every token of the end user, signed ones issued before now included |
| **Erase** | `namespaces:write` | Erases the end user in the background: tokens, runs, secrets and use. Type its id in the dialog to confirm |

The SDK does the same with [`rewind.namespaces`](/sdk/end-users).
