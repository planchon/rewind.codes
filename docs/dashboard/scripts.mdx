Scripts are content-addressed: two runs of the same source are runs of one script. The Scripts view lists every distinct
script executed since the first run, the most recently run first.

Each row shows the script's title and its first line, its runs and their outcomes, the tools it called, and when it
last and first ran.

A script's title is the first line of the comment at its top, and the rest of the comment its description:

```ts
/**
 * Triage new GitHub issues
 *
 * Labels each new issue, and asks for an approval before closing a duplicate.
 */
import { github } from "rewind:tools";
```

Your agents write it when they write the script. On a script's page, **Edit the title** gives it a title and a
description for your organization, over its comment's (`scripts:write`); removing it shows the comment's again. A run
of a script without a title shows its workflow's name, else "Untitled script".

Search with the same query bar as the runs, which reads an end user and a tool here: `namespace:alice` shows the
scripts Alice's runs ran, counted over her runs only; `tool:github.close_issue` the scripts that closed issues. Click a
tool in a row to add it to the query. An end user's page opens the same list with **See its scripts**. The list comes
from hourly counters, which carry no labels: the Scripts view is not available to a member limited to labels.

Open a script to read its full source, its tests and its runs. Its tests are the suites of the workflow versions it is
the script of, as [Testing](/dashboard/testing#a-workflow) shows them. From a run, the **Script** detail opens the same
page.

Use it to see what your models actually write: which scripts run most, which fail, and which tools they reach for.
