Observability holds the runs of your organization in four views of the same query. Its sidebar holds the view picker,
your saved searches and the filters.

## The query bar

Type a [query](/dashboard/query-language): terms separated by spaces, all of which must hold. The bar suggests fields
and the values that exist as you type (after `namespace:`, the end users whose name starts with what you typed), and
underlines a term the server cannot read.

<Frame caption="Suggestions drawn from the values that exist: here, the values of the label agent">

  <img src="/images/dashboard/observability-suggestions-dark.webp" alt="The query bar suggesting @agent:support, @agent:triage and @agent:digest" className="hidden dark:block" />

**Save** keeps the query as a saved search, in your browser; Find (<kbd>F</kbd>) opens it later.

## Filters

The sidebar lists, for each field, the values found with their counts: the timeline, the status, the namespaces, each
label, the tools, the errors, the scripts. A filter is a term of the query:

- one click asks for the value (`status:failed`);
- a second click excludes it (`-status:failed`);
- a third removes it.

## The four views

### All runs

The runs started over time, then the list: each run with its status, namespace, the first line of its script, when it
started, its duration, its calls, when it wakes and its error. Click a header to order the runs by its column (newest or
oldest first, latest activity, longest, most tool calls, soonest to wake) or to filter what it shows: a status, a
namespace, a script, a window of start, a duration, a number of calls, the tools called, an error, a label. A header's
filter is a term of the query, so it shows in the query bar and is saved with a search.

### Active

The runs not yet ended.

### Waiting

The active runs waiting on the outside world, grouped by what they wait for, by tab: **signals**, **approvals**,
**timers** and **tools**. Each run shows the line it is paused on and when it wakes, the soonest first. Use it to find
what a person, a tool or your harness has to answer.

### Failures

The failed, cancelled and aborted runs of a window, grouped by **fingerprint**: the error with its numbers, ids, times
and quoted strings replaced, so the same failure across the many scripts models write is one group. Each group shows its
runs over time, how many scripts hit it, when it was first and last seen, the line most of its runs ended at, the top
labels, and the latest run.
