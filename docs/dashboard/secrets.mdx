title: "Secrets"
description: "Your organization's secrets and each end user's: who wrote them, how often they are read, what uses them. A value is written, never shown."
---

The Secrets view lists your organization's [secrets](/sdk/secrets), the values runs use as `org/<name>`. Pick an end
user at the top of the page to see their own secrets (`ns/<name>`), in the same table, then your organization's, listed
only: those are written over every namespace.
It needs `secrets:read`; writing and deleting need `secrets:write`.

| Column | Shows |
| --- | --- |
| **Name** | The name, and how a run names it: `org/zendesk` |
| **Labels** | An organization's secret's labels: a key or a member limited to `env:prod` sees and uses only the secrets carrying it |
| **Written** | Who wrote it last (a member, a key, an end user's token) and when; hover for who created it |
| **Reads, 30 days** | Its reads per day, and how many in all |
| **Last read** | When, by which run (it opens the run), and for an organization's secret, in which namespace; or *at an action set's registration*, which reads an organization's secret to list the tools of the MCP server it is named for |
| **Used by** | What reads it now: the active runs that use it (hover for the list, those waiting on a call it serves marked), and the workflows whose latest version uses it, each opening in [Workflows](/dashboard/workflows) |

## Write a secret

**New secret** asks, in a dialog, for a name (lowercase letters, digits, `-` and `_`), the value and, for an
organization's secret, its labels. The value is typed in a password field, sent once and never shown again: no page
and no answer of the API reads it back, not even to whoever wrote it. A member limited to labels writes secrets that
carry them.

**New value** on a row replaces the value and keeps the labels. The calls parked because the secret was missing or
refused, in the runs that use it, are delivered again with the same idempotency key.

## Delete a secret

**Delete…** first reads what the secret serves, and says in the dialog what deleting it would stop:

- the active runs that use it: their next call to the server it serves is parked, until a secret of the same name is
  put again;
- those of them waiting on such a call now;
- the workflows whose latest version uses it, with the servers it serves there: for an end user's secret, their runs
  in that namespace are refused at start.

Then **Delete**, in red, deletes it. A deleted secret cannot be restored.

## Who sees what

| Permission | In this view |
| --- | --- |
| `secrets:read` | The view, the secrets' metadata and what uses them; never a value |
| `secrets:write` | **New secret**, **New value**, **Delete…** |

A member or a key limited to labels sees only the organization's secrets carrying all of them, and never writes an end
user's. The run's page names the secrets each run uses, by server, in its details.
