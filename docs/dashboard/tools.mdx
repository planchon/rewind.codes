---
title: "Tools"
description: "Latency, error rate and retries of every tool your scripts call."
---

The Tools view measures the tools behind your runs over a window: the last hour, 24 hours, 7 or 30 days.

Search them as you search the runs on the [Overview](/dashboard/overview), in one line of text that **Enter** applies:

| Term | Keeps |
| --- | --- |
| `close` | The tools whose name holds the word |
| `tool:github.close_issue`, `tool:github.*` | That tool, or every tool of a namespace |
| `toolset:5f3a9c…` | The calls of the runs of one toolset (its digest) |

Each term must hold; `-` excludes one (`-tool:github.*`). A term the view cannot read is underlined, with why. From a
run, its **Toolset** opens the view searching that toolset.

At the top: the calls completed, how many failed, the retries, and the slowest tool. Then each tool, grouped by MCP
server, group of host tools and built-ins:

| Column | What |
| --- | --- |
| **Calls**, **Failed**, **Error rate** | How many calls completed, and how many failed |
| **By kind** | The failures by kind: an error, a timeout, an unavailable server, an unknown outcome |
| **Retries** | Attempts beyond the first: calls sent again after a transient failure or a lost claim |
| **p50**, **p95**, **p99**, **max** | Latency, from the call to its result |

A slow or failing tool slows or fails every script that calls it: this is where to look when the Overview's
**Failing tools** lights up. The SDK reads the same figures with `rewind.tools.stats()`.

The Tools view is not available to a member limited to labels.
