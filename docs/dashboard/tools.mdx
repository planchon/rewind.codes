title: "Tools"
description: "Latency, error rate and retries of every tool your scripts call."
---

The Tools view measures the tools behind your runs over a window: the last hour, 24 hours, 7 or 30 days, for the
organization or one end user.

Search with the same query bar as the runs, which reads here:

| Term | Keeps |
| --- | --- |
| `namespace:alice` | The calls of one end user's runs |
| `tool:github.close_issue`, `tool:github.*` | This tool, or the tools of a server |
| `close_issue` | The tools whose name holds this text |

The figures come from hourly counters: one end user or the organization, and the tools whose name starts with what a
`tool:` term names.

At the top: the calls completed, how many failed, the retries, and the slowest tool. Then each tool, grouped by MCP
server, group of host tools and built-ins; a group folds under its row:

| Column | What |
| --- | --- |
| **Calls**, **Failed** | How many calls completed, and how many failed, with their share |
| **By kind** | The failures by kind: an error, a timeout, an unavailable server, an unknown outcome |
| **Retries** | Attempts beyond the first: calls sent again after a transient failure or an interruption |
| **p50**, **p95**, **p99**, **max** | Latency, from the call to its result |
| **Latency** | The same on one log scale for every tool: a dot at p50, a bar to p95, a tick at p99, a line to the slowest call |

A slow or failing tool slows or fails every script that calls it: this is where to look when the Overview's
**Failing tools** lights up. The SDK reads the same figures with `rewind.tools.stats()`.

The Tools view is not available to a member limited to labels.
