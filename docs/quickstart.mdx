title: "Quickstart"
description: "Register an action set, serve a harness action, run a workflow and read its result."
---

This walkthrough runs a workflow that reads a GitHub repository through the built-in `http` action and calls one
function of your own. The complete program is [`examples/quickstart`](https://github.com/planchon/rewind.codes/tree/main/examples/quickstart).

<Steps>
  <Step title="Get an API key">
    Sign in to the dashboard at [app.rewind.codes](https://app.rewind.codes), open the account menu at the bottom of
    the sidebar, then **Organization → API keys → New key**. Give it the `harness` role. The secret is shown once:
    copy it.

    <Frame>
      <img src="/images/dashboard/organization-api-key-created-light.webp" alt="A new API key, shown once after its creation" className="block dark:hidden" />
      <img src="/images/dashboard/organization-api-key-created-dark.webp" alt="A new API key, shown once after its creation" className="hidden dark:block" />
    </Frame>

    Running your own server instead? See [Self-hosting](/self-hosting): the steps below are the same with its URL.
  </Step>

  <Step title="Install the SDK">
    Node 22.12 or later. The package is ESM only and depends on no model SDK.

    <CodeGroup>
    ```bash npm
    npm install @rewind.codes/sdk
    ```

    ```bash pnpm
    pnpm add @rewind.codes/sdk
    ```
    </CodeGroup>

    The client reads its server and key from the environment:

    ```bash
    export REWIND_URL=https://api.rewind.codes
    export REWIND_API_KEY=rewind_sk_...
    ```
  </Step>

  <Step title="Register an action set">
    An action set is what workflows may call. This one enables the `http` action for `api.github.com` only, and declares
    a harness action, `notify`, that your own code executes.

    ```ts index.ts
    import { Rewind } from "@rewind.codes/sdk";

    const rewind = new Rewind();

    const actionSet = await rewind.actionSets.create({
      http: { allow: ["api.github.com"] },
      harness: [
        {
          name: "notify",
          description: "Send a short message to the user.",
          inputSchema: { type: "object", properties: { text: { type: "string" } }, required: ["text"] },
        },
      ],
    });

    console.log(actionSet.declarations.prompt);
    ```

    Rewind answers with the declarations of the action set, in a compact form for the model's prompt:

    ```text
    import { notify } from "rewind:actions";
    fetch(url, { method?, headers?, body? }) → Response · The http action, a global: HTTP requests to these hosts only: api.github.com.
    notify({ text: string }) → unknown · Send a short message to the user.
    signalUrl(name) → { url: string } · From "rewind": a URL bound to this run; what is posted to it becomes the signal `name`.
    ```
  </Step>

  <Step title="Serve the harness action">
    A worker holds a call stream open to Rewind, is handed the calls of your harness actions, runs the handler and
    answers. It runs in your infrastructure: the handler can reach your database, your users, another model.

    ```ts index.ts
    const worker = rewind.worker({
      actionSet: actionSet.id,
      actions: {
        notify: async ({ text }: { text: string }, ctx) => {
          console.log(`[notify for ${ctx.namespace}] ${text}`);
          return { sent: true };
        },
      },
    });
    ```
  </Step>

  <Step title="Run a workflow">
    In a harness, the model writes the workflow's code. Here it is a file:

    ```ts workflows/repo-report.ts
    /** The stars and open issues of a GitHub repository, sent to the user. */
    import { notify } from "rewind:actions";

    export default async function main(input: { repo: string }) {
      const res = await fetch(`https://api.github.com/repos/${input.repo}`, {
        headers: { accept: "application/vnd.github+json", "user-agent": "rewind-quickstart" },
      });
      if (!res.ok) throw new Error(`GitHub answered ${res.status} for ${input.repo}`);
      const repo = await res.json();

      const report = {
        repo: repo.full_name as string,
        stars: repo.stargazers_count as number,
        openIssues: repo.open_issues_count as number,
        pushedAt: repo.pushed_at as string,
      };
      console.log(`${report.repo}: ${report.stars} stars`);

      await notify({ text: `${report.repo} has ${report.openIssues} open issues and pull requests.` });
      return report;
    }
    ```

    Start it in the namespace of the end user it acts for, and wait up to 30 seconds for its result:

    ```ts index.ts
    import { readFile } from "node:fs/promises";

    const code = await readFile(new URL("./workflows/repo-report.ts", import.meta.url), "utf8");
    const run = await rewind.namespace("quickstart-user").runs.start({
      actionSet: actionSet.id,
      code,
      input: { repo: "nodejs/node" },
      wait: "30s",
      labels: { example: "quickstart" },
    });

    console.log(`run ${run.handle}: ${run.status}`);
    console.log(run.output?.value);
    await worker.stop();
    ```

    Code the namespace has not run before becomes one of its [workflows](/concepts/workflows), with this code as its
    version 1: the same code started again is a run of the same workflow.
  </Step>

  <Step title="Read the result">
    ```text
    [notify for quickstart-user] nodejs/node has 1326 open issues and pull requests.
    run quickstart-user/wf-4m8q2k/06h0n8tcbk20: completed
    { openIssues: 1326, pushedAt: '2026-11-15T19:15:27Z', repo: 'nodejs/node', stars: 123766 }
    ```

    The code was type-checked against the action set, ran in the sandbox, sent its request through the `http` action and
    its `notify` call to your worker. Each of these is an event of the run's history.
  </Step>

  <Step title="Look at the run">
    Open **Runs** in the dashboard and click the run. The debugger shows the code with each call next to the line that
    made it, a timeline, and a cursor that steps through the run's history.

    </Frame>
  </Step>
</Steps>
