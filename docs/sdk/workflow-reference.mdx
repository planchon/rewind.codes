## `rewind`

```ts
import { sleep, signal, signalUrl, run, ActionError, CancelledError, RunError } from "rewind";
```

### `sleep(duration)`

```ts
function sleep(duration: Duration): Promise<void>;
```

Waits for `duration`: a number of milliseconds, or a string such as `"30s"`, `"10d"` or `"1h30m"` (units `ms`, `s`,
`m`, `h`, `d`, `w`). The wait is durable: the run survives restarts and deploys, and costs nothing while it waits.
Afterwards, `Date.now()` is at least the time before plus `duration`.

### `signal(name, opts?)`

```ts
function signal<T = unknown>(name: string): Promise<T>;
function signal<T = unknown>(name: string, opts: { timeout: Duration }): Promise<T | undefined>;
```

Waits for the next signal named `name` sent to this run, and returns its payload. A signal sent before the code waits
is kept in the name's mailbox, first in, first out, so none is lost. With a timeout, returns `undefined` if none arrived
in time; without one, the wait lasts as long as the run. Names starting with `rewind:` are reserved.

In a run of a version that declares its signals, `name` must be one of them, and the payload has the declared type.

### `signalUrl(name)`

```ts
function signalUrl(name: string): Promise<{ url: string }>;
```

Returns a unique URL bound to this run and the signal `name`: every request posted to it becomes a signal `name` on
this run, with the request's body as payload. Give the URL to an external system, then wait with `signal(name)`.

### `run`

```ts
const run: { readonly id: string; readonly startedAt: Date };
```

This run. A fork has its own id, so code that reads `run.id` diverges from its source there.

### `ActionError`

Thrown by a call to an action that failed. Catch it to handle the failure; uncaught, it fails the run.

| Property | What |
| --- | --- |
| `message` | What went wrong, written for a model |
| `action` | The action that failed, such as `github.close_issue` |
| `outcomeUnknown` | The call was interrupted and may or may not have taken effect: check before calling the action again |
| `data` | What the action returned with its error, if anything |

### `CancelledError`

Rejects every pending `await` of the code when the run is cancelled. Catch it to clean up: the code then has one grace
step to end by itself.

### `RunError`

Thrown by `result()` when a child run this run started failed, was cancelled or aborted, or returned an output its
workflow's schema refuses.

| Property | What |
| --- | --- |
| `workflow` | The workflow, such as `triage` |
| `runId` | The run that ended so |
| `status` | `"failed"`, `"cancelled"`, `"aborted"` or `"invalid_output"` |

## `rewind:actions`

Generated for the run's action set: one export per group, an MCP server (by the name the action set gives it), an API
or a group of harness actions, and one per harness action without a group. Each action is an async function taking one
object of arguments.

```ts
import { github, slack, ask_user } from "rewind:actions";

const issues = await github.list_issues({ repo: "acme/api", state: "open" });
```

Arguments are validated against the action's schema before the call is recorded: invalid arguments throw a `TypeError`
at the call site. A failed call throws an `ActionError`.

## `rewind:workflows`

Generated for the run's action set: one export per organization workflow it pins.

```ts
import { triage } from "rewind:workflows";
```

| Call | Does |
| --- | --- |
| `triage.start(input, opts?)` | Starts a child run of the pinned version; resolves with its handle once it exists. `opts`: `detached`, `labels`, `ttl` |
| `run.id` | The child run's id |
| `run.signal(name, payload)` | Sends one of the workflow's signals; resolves once it is in the run's mailbox. Throws an `ActionError` if the run has ended |
| `run.result()` | The run's output once it has ended; throws a `RunError` otherwise |
| `run.result({ timeout })` | The output, or `undefined` if the run has not ended in time |
| `triage.get(runId)` | A handle on an existing run of the workflow, to signal it |

A child run started without `detached: true` is attached: this run does not end before it, and cancels it if this run
fails or is cancelled.

## Globals

The sandbox has the ECMAScript built-ins (ES2025, `Temporal`, explicit resource management) and exactly these globals:

| Global | Behavior |
| --- | --- |
| `Date`, `performance.now()`, `Temporal.Now`, `Intl.DateTimeFormat` | Logical time, identical on replay |
| `Math.random()`, `crypto.getRandomValues()`, `crypto.randomUUID()` | Seeded per run |
| `setTimeout`, `setInterval`, `clearTimeout`, `clearInterval` | Durable timers |
| `console` | Log lines, recorded in the history |
| `URL`, `URLSearchParams`, `TextEncoder`, `TextDecoder`, `atob`, `btoa`, `structuredClone`, `queueMicrotask` | Standard |
| `fetch` | Only with the action set's `http` action, to its allowed hosts. A subset of the web's: no `Request`, `Response` or `Headers` constructors, no streams, no `AbortSignal` |

The isolate runs with `TZ=UTC` and the `en-US` locale. See [The sandbox](/concepts/sandbox) for what is removed and why.

<Note>
  Code written before Rewind's current names keeps running: the sandbox still resolves `rewind:tools`, `webhook()`,
  `ToolError` and `WorkflowError` for it, as `rewind:actions`, `signalUrl()`, `ActionError` and `RunError`. New code
  must use the names on this page: the old ones are declared nowhere, so they do not type-check.
</Note>
