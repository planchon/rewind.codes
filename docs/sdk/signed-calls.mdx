---
title: "Signed calls"
description: "Your own APIs and MCP servers check that a call comes from Rewind, and for which end user, with verifyRewindCall: no secret of yours stored in Rewind."
---

With `auth: { type: "rewind" }` on an API or an MCP server of an [action set](/sdk/action-sets#how-calls-prove-who-calls),
Rewind signs each request with your organization's Ed25519 key. Your server checks the signature with the public key,
and learns the end user from the signature, not from an argument the model wrote. Rewind keeps no secret of yours.

```ts
const actionSet = await rewind.actionSets.create({
  apis: [{ name: "dax", openapi: "https://api.dax.example/openapi.json", auth: { type: "rewind" } }],
});
```

## What a call carries

`Authorization: Bearer <JWT>`, signed with `EdDSA`, valid 60 seconds:

| Claim | Value |
| --- | --- |
| `iss` | `https://api.rewind.codes/organizations/<your organization>`: its public keys are at `{iss}/jwks.json` |
| `aud` | The API's `baseUrl`, or the MCP server's URL |
| `sub` | The run's namespace: the end user the call acts for |
| `labels` | The run's labels |
| `run`, `action` | The run's id, and the action called (`dax.createMeasure`) |
| `idempotency_key` | `{run_id}/{seq}`: the same on every delivery of the call |
| `jti` | `{run_id}/{seq}/{delivery}`: one per request |
| `htm`, `htu`, `body` | The method, the URL, and the SHA-256 of the body in base64url (absent without a body) |
| `iat`, `exp` | Now, and 60 seconds later |

## Check it with `verifyRewindCall`

`verifyRewindCall(request, { issuer, audience, labels? })` does every check your server must do:

- the signature, with a key of `{issuer}/jwks.json` (fetched once and cached; a key with an unknown `kid` is fetched
  again at most every 10 seconds, which follows a rotation);
- `iss` is the issuer you expect, `aud` your own;
- `exp` has not passed and `iat` is not in the future, with 5 seconds of leeway;
- `htm`, `htu` and `body` match the request: a JWT replayed on another method, URL or body is refused;
- the run carries `labels`, when you give them.

It answers `{ namespace, labels, run, action, idempotencyKey }`, or throws a `RewindSignatureError` whose `check` names
what failed (`signature`, `kid`, `iss`, `aud`, `exp`, `iat`, `htm`, `htu`, `body`, `labels`, `token`). Answer it with a
**401**: Rewind parks the call. When the public keys cannot be fetched, it throws a `RewindConnectionError`: answer a
**503**, which Rewind treats as a transient failure and delivers again.

Your issuer is in the dashboard, under Organization › [Signing keys](/dashboard/organization#signing-keys), in
`(await rewind.signingKeys.list()).issuer`, and `rewindIssuer(url, organizationId)` builds it from your server's URL and
your organization's id.

    import { RewindSignatureError, verifyRewindCall } from "@rewind.codes/sdk";

    const ISSUER = process.env.REWIND_ISSUER!; // https://api.rewind.codes/organizations/org_…
    const AUDIENCE = "https://api.dax.example";

    export async function POST(request: Request): Promise<Response> {
      let call;
      try {
        call = await verifyRewindCall(request, { issuer: ISSUER, audience: AUDIENCE, labels: { env: "prod" } });
      } catch (error) {
        if (error instanceof RewindSignatureError) return Response.json({ error: error.check }, { status: 401 });
        return new Response(null, { status: 503 });
      }
      // The body is read from a clone: the request's own is still there.
      const measure = await createMeasure(call.namespace, await request.json(), call.idempotencyKey);
      return Response.json(measure, { status: 201 });
    }

    import express from "express";
    import { RewindSignatureError, verifyRewindCall, type RewindCall } from "@rewind.codes/sdk";

    const app = express();
    app.set("trust proxy", true); // req.protocol and req.get("host") are the public ones behind a proxy

        next();

        if (error instanceof RewindSignatureError) return res.status(401).json({ error: error.check });
        next(error);
      }
    });

      const call: RewindCall = res.locals.call;

- **`url` is the one the client called.** Behind a proxy or a load balancer, rebuild the public URL (scheme, host,
  path and query), as above; a URL rewritten on its way fails the `htu` check.
- **The body is the raw bytes.** A body parsed as JSON cannot be hashed: keep the raw one (`express.raw()`,
  `express.json({ verify })`, NestJS's `rawBody: true`).
- **`call.idempotencyKey`** is the same on every delivery of a call. Store it with the effect, and a call delivered
  again after a timeout does not act twice.

## Check `labels` when environments share an organization

One key signs every run of the organization, whatever its labels. When development and production share an
organization, a key limited to `env=dev` may still register an action set that names your production server, and its
runs would reach it with a valid signature. Give your production server `labels: { env: "prod" }`: it then refuses the
calls of every run not labelled `env=prod`. A run's labels are set by whoever starts it and by the key's grant, never
by the workflow's code.

## Replays

`htm`, `htu` and `body` bind a signature to one request, and it expires after 60 seconds. A server that checks the
signature alone would accept a JWT replayed within those 60 seconds, on the same method, URL and body: refuse an effect
already done for the same `idempotencyKey` if that matters to you.

## MCP servers

Each HTTP request of an MCP session is signed. Those of a call carry `sub`, `labels`, `run`, `action` and
`idempotency_key`; the others (`initialize`, the listing of the tools when the action set is registered) only `iss`,
`aud`, `jti`, `htm`, `htu`, `body`, `iat` and `exp`. Pass `session: true`: such a request is answered `null` rather than
refused.

```ts
const call = await verifyRewindCall(request, { issuer, audience: "https://mcp.example.com/mcp", session: true });
if (call === null) {
  // initialize or tools/list: signed by your organization, outside any call
}
```

## Rotate the key

`rewind.signingKeys.rotate()`, or Rotate in the dashboard (`organization:write`), replaces the key: the old one stops
signing at once and stays published for 24 hours, so a call it signed is still accepted. `verifyRewindCall` fetches the
new key when it first meets its `kid`. A server that refuses a signature answers 401: the call is parked, and your
harness approves it once the server accepts the key again.
