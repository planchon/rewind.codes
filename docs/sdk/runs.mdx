## Start a run

A run executes one version of a [workflow](/concepts/workflows) for one end user: give the code with an action set, or
name an existing workflow.

```ts
const run = await rewind.namespace(user.id).runs.start({
  actionSet: actionSet.id,
  code,
  input: { repo: "acme/api" },
  wait: "30s",
  idempotencyKey: toolCall.id,
  labels: { agent: "triage", conversation: conversation.id },
  traceparent,
  ttl: "7d",
});

run.workflow; // { id: "wf_7k2m9q4x8d1c", name: null }: code new to the namespace is a new workflow's version 1
```

<ParamField body="code" type="string">
  The TypeScript source: one ES module whose default export is the entry point. The run is a run of the workflow that
  already has this code in the namespace, or among the organization's workflows; else the start creates a workflow in
  the namespace, with this code as its version 1. Or give `workflow` instead: both is refused (422).
</ParamField>
<ParamField body="actionSet" type="string">
  The action set the code imports from `rewind:actions`, with `code`.
</ParamField>
<ParamField body="workflow" type="string">
  Instead of code: a workflow by its id or its name, `"triage"` for its latest version, `"triage@v12"` or
  `"triage@<digest>"` for one version. A name resolves in the namespace first, then among the organization's
  workflows. The version brings its code, action set and secrets; the input is checked against its input schema.
</ParamField>
<ParamField body="input" type="unknown" default="{}">
  The argument of `main`: any JSON value.
</ParamField>
<ParamField body="wait" type="Duration">
  Wait up to this long for the run to end. The run is returned as it is then: ended, or still active with what it waits
  for. Without it, the call returns once the run is created, before it ran.
</ParamField>
<ParamField body="idempotencyKey" type="string">
  A request repeated with the same key returns the run the first one started, instead of starting another.
</ParamField>
<ParamField body="labels" type="Record<string, string>">
  Your metadata: the agent, the conversation, the environment. Labels filter runs in the API and the dashboard, scope
  `list_runs`, keys and tokens limited to labels, and webhook subscriptions. The code never sees them.
</ParamField>
<ParamField body="traceparent" type="string">
  The W3C trace context of the caller, typically the LLM call that wrote the code: the run appears under it in your
  traces. `tracestate` too.
</ParamField>
<ParamField body="ttl" type="Duration" default="30d">
  The run's time to live: it is cancelled at its deadline. Bounded by the end user's `maxTtl`.
</ParamField>
<ParamField body="check" type="boolean" default="true">
  Type-check the code before starting it. Refused code throws `RewindApiError` with the slug `invalid-code` and its
  `diagnostics`. A workflow's version is not checked again: it was checked when it was made.
</ParamField>
<ParamField body="secrets" type="Record<string, string>">
  The [secrets](/sdk/secrets) the run uses, by MCP server or API: `{ github: "ns/github", zendesk: "org/zendesk" }`.
  Names, never values; required for each server the code imports whose `auth` takes a secret. A run of a `workflow`
  gives none: its version's are read. A refused secret throws `secret-required`, whose `secrets` say which ones the
  caller may use instead.
</ParamField>

## Read a run

```ts
const run = await rewind.runs.get(id, { wait: "10s" }); // wait for it to end, up to 10 s

run.status; // "queued" | "running" | "waiting" | "completed" | "failed" | "cancelled" | "aborted"
run.handle; // "user_ada/triage/06bqx3k9f2mt": its namespace, its workflow's name or short id, a suffix
run.workflow; // its workflow's id and name; run.version, the version's number
run.output?.value; // with completed: what main returned
run.error; // with failed or cancelled: name, message, location, code frame, the call that failed
run.waitingFor; // with waiting: the signals, timers, calls and quarantine it waits for
run.logs; // the last 20 console lines
run.namespace; // the end user
```

An **active** run has not ended: it is `queued` until its first step is committed, `running` while a step is in
progress or Rewind is making one of its calls (to an MCP server, an API or `http`), and `waiting` when nothing Rewind
does can move it until something arrives. Each item of `waitingFor` has a `kind`: `signal`, `timer`, `quarantined`, or
`call`, with the call's `state`: `ready` or `claimed` for a harness action, `approval`, `deferred` or `parked`.

The API takes a run's id or its handle wherever it takes a run.

Values (`input`, `output`, call arguments and results) are payloads: `{ digest, bytes, preview, value }`. A value
larger than 256 KiB is left out; read it through its run with `rewind.payloads.get(digest, { run: run.id })`.

## Follow a run live

`events` is an async iterator over the events of the run's history as they are committed. A dropped connection resumes
after the last event received.

```ts
for await (const message of rewind.runs.events(run.id, { follow: true })) {
  if (message.type === "end") break;
  console.log(message);
}
```

## The transcript, for a model or a human

`transcript` returns the run as text for a model: a header, then one line per event with its line, its outcome and its
timing.

```ts
const transcript = await rewind.runs.transcript(run.id);
const event = await rewind.runs.event(run.id, 7); // one event of its history in full, by its position
```

## Search runs

Runs are searched with the [query language](/dashboard/query-language), the same as the dashboard's query bar and the
CLI.

```ts
const page = await rewind.runs.list({ q: "@agent:triage status:failed,aborted started:>now-24h", sort: "activity" });
for await (const run of rewind.runs.listAll({ q: "waiting:approval" })) console.log(run.handle);

const since = new Date(Date.now() - 24 * 3600_000);
const stats = await rewind.runs.stats({ q: "namespace:user_ada", since }); // counts by status, series, facets
const failures = await rewind.runs.failures({ since }); // failed runs by fingerprint
```

`sort` orders them: `started` (the default, the most recently started first), `oldest`, `activity` (the most recent
activity first), `wakes` (the soonest to wake by itself first), `duration` (the longest first, the runs that have not
ended last) or `calls` (the most calls first). Filters also exist as parameters: `status`, `waiting`, `labels`,
`action`, `error`, `workflow`, `startedBy`, `source`. A query that cannot be read is refused with `invalid-query`, and
the error says where the term at fault is.

The statistics (`runs.stats`, `runs.failures`, the counts of `workflows.list`, `actions.stats`) come from hourly
counters: their scope is one end user (a single `namespace:` term in `q`) or the whole organization, over a window of
whole hours (`since`, `until`), stepped by `interval`. Any other term is refused with `invalid-query`, and a key or a
token limited to labels is refused (403): counters carry no labels.

## Cancel a run

Every pending `await` of the code rejects with `CancelledError`, and the code gets one grace step to clean up.

```ts
const run = await rewind.runs.cancel(id, { reason: "the user closed the conversation", wait: "10s" });
```

## Fork a run with corrected code

A fork reuses its source's recorded results while the corrected code makes the same calls, then continues live: the
calls already made are not made again. This is what the agent tool `retry_run` does.

```ts
const fixed = await rewind.runs.fork(failed.id, {
  code: correctedCode,
  wait: "30s",
  // at: 12,          go live from this event, even if the calls still match
  // input: { ... },  another input than the source's
  // secrets: { ... }, other secrets than the source's
});
```

The fork has its own id and TTL, and its source's seed, input, action set, namespace and secrets. Its secrets are
checked against your rights, since its code is new. The fork's `source` names the run it came from, and its handle keeps
its source's origin. Its corrected code does not become a version of the source's workflow: the fork is a run of the
workflow that already has that code in the namespace, or of a new one; make it a version of the workflow with
[`workflows.createVersion`](/sdk/workflows#versions-and-the-gate).

## Export a run

```ts
const exported = await rewind.runs.export(run.id); // the run export: its code, action set and history, which replays on its own
const cassette = await rewind.runs.export(run.id, { as: "cassette" }); // its calls and signals, for tests
```

## Quarantine and deletion

A run whose replay diverged from its history, or whose activations failed 5 times in a row, is quarantined
(`run.quarantine` says why). It is not failed: it is `waiting`, for `quarantined`. Fix the cause, then release it, or
give it up.

```ts
await rewind.runs.release(id); // activated again
await rewind.runs.giveUp(id); // ends aborted
await rewind.runs.delete(id); // erases the run: its history, its archive and its payloads
```
