## Errors

The API answers errors as `application/problem+json`. The SDK throws them as `RewindApiError`; test their kind with
`isProblem`.

```ts
import { isProblem, RewindConnectionError } from "@rewind.codes/sdk";

try {
  await rewind.namespace(user.id).runs.start({ actionSet: actionSet.id, code });
} catch (error) {
  if (isProblem(error, "invalid-code")) {
    for (const d of error.diagnostics) console.log(d.message, d.frame);
  } else if (isProblem(error, "quota-exceeded")) {
    console.log(error.quota); // { quota, scope, limit, used, resetsAt }
  } else if (error instanceof RewindConnectionError) {
    // the server could not be reached
  } else throw error;
}
```

| Property | What |
| --- | --- |
| `status` | The HTTP status |
| `slug` | The kind of problem, below |
| `detail` | What went wrong, written for a model |
| `diagnostics` | For refused code: the type-checker's findings, with location and code frame |
| `query` | For a query that cannot be read: where the term at fault is, in characters |
| `quota` | For `quota-exceeded`: which quota, at which scope, its limit, the use, and when it frees |
| `tests` | For `tests-failed`: each test's outcome, those that did not pass with their problem and failures |
| `secrets` | For `secret-required`: each server at fault (`server`, `problem`, `secret`) and the secrets the caller may use for it |

| Slug | Means |
| --- | --- |
| `invalid-request` | A malformed request |
| `invalid-code` | The code was refused by the checks: see `diagnostics` |
| `invalid-action-set`, `invalid-workflow` | The action set cannot be registered; a workflow's name, a signal's name or a schema cannot be used |
| `name-taken` | The workflow's scope already has a workflow of that name |
| `not-forkable`, `not-a-fork` | Only an organization's workflow is forked; only a fork pulls |
| `invalid-test` | A test or a suite was refused: an invalid test, a stored test that does not exist, a retired or updated test that is not in the suite or has no reason, two tests of the same name |
| `tests-failed` | Tests did not pass: the workflow version was not made, the tests not added, or the fork not created; see `tests` |
| `invalid-input` | A workflow's input does not match its schema |
| `secret-required` | A run, a fork or a workflow version was refused before it existed: a server that takes a secret has none named, a secret is named for a server that takes none or does not exist, or the caller may not use it; see `secrets` and [Secrets](/sdk/secrets#when-a-secret-is-refused) |
| `invalid-signal` | A reserved signal name, or a signal a version does not declare or whose payload does not match |
| `invalid-query` | A query that cannot be read |
| `unauthorized`, `forbidden` | No valid key or token; or the caller lacks a permission |
| `not-found` | Missing, or not visible to the caller: another end user's run or workflow answers this |
| `run-ended` | The run has ended: it takes no signal or cancellation |
| `quota-exceeded` | An end user's limit, or your organization's ceiling, is reached |
| `call-gone`, `call-not-waiting` | A call that no longer waits for this answer, or that waits for no approval |
| `action-set-unavailable` | An MCP server or an API of the action set could not be reached or refused, or its OpenAPI document could not be read |
| `payload-too-large` | A value above the size the API takes |
| `namespace-deleting` | The end user is being erased |
| `unavailable`, `internal` | A fault of the service |

Two more errors come from the SDK itself:

- **`NamespaceRequiredError`**: a key's client started a run, or checked or tested code, without naming the end user
  (`rewind.namespace(name)`).
- **`RewindConnectionError`**: the server could not be reached.

All of them extend `RewindError`.

## Redeliveries

A request that is safe to repeat is sent again after a network error or a 503, twice by default (`maxRetries`):
reads, `PUT`, `DELETE`, action set registration and workflow creation (both find what they already made), checks and
tests, and every request that carries an idempotency key.

Starting a run, forking it or sending a signal **without** an idempotency key is never sent again, nor is minting a
token. Give them a key, and they become safe to send again:

```ts
await rewind.runs.start({ actionSet: actionSet.id, code, idempotencyKey: toolCall.id });
await rewind.runs.signal(runId, "approval", { close: true }, { idempotencyKey: `approval-${decision.id}` });
```

## Waiting

`runs.start`, `runs.get`, `runs.fork` and `runs.cancel` take `wait`: they answer when the run ends or `wait` passes,
whichever comes first. A wait longer than 50 seconds is split into several requests, so proxies and HTTP timeouts never
cut it. Every call also takes an `AbortSignal` as `signal`.

The event stream (`runs.events(id, { follow: true })`) reconnects after a dropped connection, from the next event, up
to 5 times by default (`maxReconnects`).
